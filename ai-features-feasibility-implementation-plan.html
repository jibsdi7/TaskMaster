Feature 1 — Natural Language Workflow Generator Feasible
Input: "Login to application, search customer, download report" → Output: Draft workflow with nodes + edges, ready to save and run

How it would work

User types intent→ POST /api/ai/generate-workflow→ LLM (GPT-4o)→ Structured JSON (nodes + edges)→ WorkflowGeneratorService→ Draft workflow rendered on canvas

What the LLM receives (prompt)

  • User's natural language instruction
  • System prompt listing all available NodeType values and their config shapes
  • A few worked examples (few-shot)
  • Strict JSON schema to force structured output

What the LLM returns (JSON)

  • Array of { node_type, label, config } objects
  • No selectors — those are set to empty placeholders
  • Workflow name & description
  • Optional step-level hints (e.g., "user must fill URL")

Codebase hooks — what already exists

  • WorkflowGeneratorService.generate_from_actions() already converts an actions list → nodes + edges. The LLM output just needs to conform to the same action schema.
  • WorkflowNodeCreate Pydantic schema handles all 14 node types with typed configs — use it to validate LLM output before saving.
  • workflowStore.setNodes() / setEdges() on the frontend can load a draft workflow onto the canvas without a save round-trip.
  • nodeTemplates.ts → STATIC_NODES gives the full node catalogue to inject into the system prompt.

Key design decision — graceful degradation

If OPENAI_API_KEY is not set, ai_generator.py falls back to a rule-based parser that matches keywords like "login", "search", "click", "download" to known node types. This means the feature works offline / without API cost for common cases.

Feature 2 — Workflow Documentation Generator Feasible (LLM optional)
Input: Existing workflow (nodes + edges + run history) → Output: Human-readable Markdown / HTML documentation

Two implementation tiers

Tier 1 — Rule-based (no LLM)

  • Iterate nodes in topological order
  • Template each node type into a plain-English sentence ("Navigate to url", "Click the Dogs link")
  • Append run stats from WorkflowRun (avg duration, pass/fail rate)
  • Outputs Markdown → served as a download or shown in a dialog
  • Zero external dependencies

Tier 2 — LLM-enriched

  • Same rule-based output as the prompt context
  • LLM adds: purpose summary, business context, edge-case warnings
  • Richer prose, suitable for handoff docs
  • Reuses the same OPENAI_API_KEY from Feature 1

Codebase hooks — what already exists

  • ScriptGenerator.generate() already serialises nodes in topological order — the same ordering can drive the doc generator.
  • GET /api/workflows/{id}/export-script endpoint pattern can be copied verbatim for GET /api/workflows/{id}/export-docs.
  • WorkflowRun model has duration_seconds, status, and result — ready to include as test history.
  • topological_sort() in script_generator.py is already importable for traversal order.

Shared Implementation Concerns

LLM API key management

  • Add OPENAI_API_KEY to config.py + .env.example
  • Never commit the actual key — already covered by existing .gitignore
  • Expose a GET /api/ai/status endpoint that returns { available: bool } so the UI can hide/show AI buttons

LLM output validation

  • Use OpenAI's structured outputs (JSON mode) with a strict schema matching WorkflowNodeCreate
  • Validate every returned node through the existing Pydantic schema before touching the DB
  • If validation fails, return a user-friendly error — never a 500

Cost & latency

  • NL generator: ~1–2 LLM calls per workflow draft, ~1–3s latency
  • Doc generator (Tier 1): zero LLM calls, <100ms
  • Doc generator (Tier 2): 1 call, ~2s
  • No streaming required — simple request/response is sufficient

Recommended LLM

  • OpenAI GPT-4o — best structured-output reliability
  • Claude 3.5 Sonnet — strong alternative, same REST shape
  • Use litellm as a thin abstraction so you can swap providers via config
